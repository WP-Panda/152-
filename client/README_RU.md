# WP Panda Updater — руководство по клиенту и интеграции

Документ предназначен разработчику плагина/темы, который встраивает SDK в продукт, и администратору сайта-клиента, который вводит лицензию. Клиентская часть не исполняет серверную панель: она обращается к REST API издателя по HTTPS и подключает приватные пакеты к стандартной системе обновлений WordPress.

## 1. Важно о лицензии

Клиент получает индивидуальный ключ, который издатель выпускает с лимитом на 1, 3 или 5 сайтов. Ключ активируется отдельно на каждом сайте; список и занятые слоты контролируются сервером.

**Лицензия не влияет на работоспособность продукта, а только на получение обновлений.** Без ключа или при невалидном ключе WordPress всё равно покажет, что вышла новая версия; получить ZIP и установить обновление можно только с действующей лицензией, активированной для этого сайта. Продукт продолжает выполнять свои функции и при ошибке лицензии, и при недоступности сервера. SDK не отключает функции плагина/темы и не является DRM.

Ключ не встраивайте в исходный код или ZIP. После первоначальной установки клиент вводит его в админке своего WordPress. SDK сохраняет ключ в опции WordPress без автозагрузки, а сервер получает его только по HTTPS.

## 2. Что находится в каталоге client/

- `client/wp-panda-updater.php` — основной SDK-клиент; копируется в поставку плагина или темы либо в MU-plugin каталог.
- `client/loaders/wp-panda-plugin-updater-loader.php` — необязательный MU-loader для private-плагинов, включая неактивные.
- `client/loaders/wp-panda-theme-updater-loader.php` — необязательный MU-loader для установленных тем, включая неактивные.

Требования SDK: WordPress **5.8+**, PHP **7.4+**, доступный из PHP исходящий HTTPS-запрос к серверу Vault. Серверные требования и установка описаны в [server/README_RU.md](../server/README_RU.md).

## 3. Как подключить SDK к плагину

### 3.1 Подготовьте пакет

1. Добавьте `client/wp-panda-updater.php` в дистрибутив, обычно рядом с главным файлом плагина.
2. Убедитесь, что slug каталога соответствует slug продукта в Vault, например `panda-seo`.
3. В главном PHP-файле после заголовка плагина подключите SDK и создайте updater:

```php
<?php
// Plugin Name: Panda SEO
// Version: 1.2.0

require_once __DIR__ . '/wp-panda-updater.php';

new WP_Panda_Updater(array(
    'type'        => 'plugin',
    'slug'        => 'panda-seo',
    'name'        => 'Panda SEO',
    'version'     => '1.2.0',
    'api_url'     => 'https://updates.example.com/wp-json/wp-panda/v1',
    'plugin_file' => __FILE__,
));
```

Замените URL на REST namespace своего сервера Vault. Это именно корень API, без `/check`. Явный `plugin_file` (`__FILE__` в главном файле) надёжно связывает ответ WordPress с обновляемым плагином. Если опустить аргумент, SDK пытается определить основной файл по backtrace; для нестандартной загрузки всегда задавайте его явно.

`version` должен совпадать с `Version:` заголовка плагина и увеличиваться при выпуске. `slug` совпадает со slug продукта в Vault и каталогом верхнего уровня ZIP. Тип — строго `plugin`.

### 3.2 Функции и ограничения

SDK подключает стандартные WordPress update hooks. При проверке он отправляет slug, тип, установленную версию и `home_url('/')`; если ключ сохранён, передаёт его в `Authorization: Bearer ...`. Метаданные о новой версии публичны, поэтому обновление отображается и без ключа или с невалидным ключом. В таком случае WordPress сможет показать предложение обновления, но защищённый endpoint откажет при попытке получить ZIP. Подписанная ссылка доступна только для активной лицензии и повторно проверяется сервером в момент скачивания. Результат проверки кэшируется до пяти минут отдельно для каждого состояния ключа.

Поставляемый код содержит URL API, имя/slug/версию, но не клиентскую лицензию. Не помещайте индивидуальный ключ ни в этот файл, ни в настройку по умолчанию, Git или общую сборку продукта.

## 4. Подключение SDK к теме

Скопируйте SDK в корень темы и подключите из `functions.php`:

```php
<?php
require_once get_stylesheet_directory() . '/wp-panda-updater.php';

$panda_theme = wp_get_theme();
new WP_Panda_Updater(array(
    'type'    => 'theme',
    'slug'    => $panda_theme->get_stylesheet(),
    'name'    => $panda_theme->get('Name'),
    'version' => $panda_theme->get('Version'),
    'api_url' => 'https://updates.example.com/wp-json/wp-panda/v1',
));
```

`slug` должен соответствовать каталогу темы и продукту типа `theme` в Vault. Для дочерней темы обычно используется stylesheet slug текущей темы; проверьте, что именно такой slug зарегистрирован и ZIP имеет соответствующее имя каталога.

Тема должна сохранять свои локальные изменения в подходящем месте: штатное обновление заменяет каталог продукта, как и обычное обновление WordPress.

## 5. Экран лицензии: автоматический или собственный

### 5.1 Автоматическая страница по умолчанию

Если экземпляр SDK зарегистрирован без параметра `settings_page`, он добавляет страницу в админке клиента: **Настройки → Panda Updates**. Для каждого подключённого продукта показывается отдельное поле. Несколько лицензий (плагинов/тем) могут управляться с этой страницы.

На странице есть поле пароля для ключа, кнопка **Активировать лицензию**, а после сохранения — **Заменить ключ**, **Деактивировать сайт** и **Удалить ключ локально**. Интерфейс прямо показывает обязательное пояснение рядом с ключом:

> Лицензия не влияет на работоспособность продукта, а только на получение обновлений.

Первую версию с SDK клиент устанавливает вручную. После этого администратор вводит полученный от издателя ключ, активирует его и получает последующие версии через **Консоль → Обновления**.

При желании страницу по умолчанию можно поместить под существующий пункт меню WordPress, передав `settings_parent` — родительский menu slug. Например, `'settings_parent' => 'options-general.php'` добавляет подменю в «Настройки». Используйте этот аргумент только если хотите переместить общую Panda Updates страницу.

### 5.2 Вывод поля в существующей странице настроек продукта

Если у продукта уже есть собственная страница настроек, выведите блок SDK в её callback-функции. Чтобы SDK не создавал дополнительную страницу Panda Updates для этого экземпляра, передайте непустой `settings_page` в конструктор. Значение может быть slug существующей страницы; это указатель «используется собственная страница», SDK сам не регистрирует эту страницу.

```php
require_once __DIR__ . '/wp-panda-updater.php';

new WP_Panda_Updater(array(
    'type'        => 'plugin',
    'slug'        => 'panda-seo',
    'name'        => 'Panda SEO',
    'version'     => '1.2.0',
    'api_url'     => 'https://updates.example.com/wp-json/wp-panda/v1',
    'plugin_file' => __FILE__,
    'settings_page' => 'panda-seo-settings', // slug собственной страницы; отключает автодобавление Panda Updates
));

function panda_seo_render_settings_page() {
    echo '<div class="wrap"><h1>Panda SEO</h1>';
    // Здесь может быть существующая форма настроек продукта.
    echo '<form method="post" action="options.php">';
    // Поля настроек...
    wp_panda_updater_license_field('panda-seo', 'plugin');
    submit_button();
    echo '</form></div>';
}
```

`wp_panda_updater_license_field($slug, $type = 'plugin')` — глобальная функция SDK. Вызовите её после создания `WP_Panda_Updater`, когда выполняется рендер собственной админ-страницы. Для темы используйте `wp_panda_updater_license_field('my-theme', 'theme')`. Функция выводит блок и возвращает `true`, если продукт зарегистрирован и у пользователя есть `manage_options`; иначе ничего не печатает и возвращает `false`.

**Блок не создаёт `<form>`**: его можно безопасно разместить внутри существующей формы. Кнопки имеют `type="button"`, сохраняются только по AJAX и не отправляют/не блокируют остальные настройки. Клиентский администратор должен иметь capability `manage_options`.

Важно: если добавить `'settings_page'`, но забыть вызвать helper в реальном callback страницы, поле нигде не появится. Если helper не вызван, но `settings_page` не задан, пользователь увидит дополнительную общую страницу. Slug в helper должен точно совпадать с `slug` зарегистрированного SDK, а `type` — с типом продукта.

## 6. Активация и управление ключом администратором сайта

1. Получите ключ и лимит от поставщика продукта.
2. Установите первую сборку продукта, содержащую SDK (первичную установку нельзя получить через Vault, если продукт ещё не подключён).
3. Откройте **Настройки → Panda Updates** или страницу настроек продукта, где разработчик вставил поле.
4. Введите ключ и нажмите **Активировать лицензию**. Для активации требуется интернет-доступ клиента к HTTPS API Vault.
5. Убедитесь, что отображена успешная активация, затем проверьте обновления WordPress.
6. Для переноса на новый домен деактивируйте сайт на старом до отключения, затем активируйте ключ на новом. Если старый сайт недоступен, обратитесь к издателю для ручного освобождения слота.

При достижении лимита сервер вернёт ошибку; нужно освободить старую площадку или запросить у поставщика лицензию с большим количеством сайтов. Повторная активация того же host/path идемпотентна. HTTP и HTTPS одной площадки считаются одинаково; поддомены и отдельные установки в подкаталогах могут занимать отдельные слоты.

### Действия в поле

- **Заменить ключ**: активирует введённый новый ключ, затем пытается деактивировать прежний; если старый сервер недоступен, старую активацию может потребоваться удалить вручную в Vault.
- **Деактивировать сайт**: отправляет серверу запрос, удаляет текущую серверную активацию и после успеха удаляет ключ локально.
- **Удалить ключ локально**: только стирает option на этом сайте. Если сервер не получил deactivation, слот остаётся занят; попросите издателя освободить его через Panda Vault.

Ключ в базе клиентского WordPress доступен администраторам/системным операторам с доступом к базе или файлам. Храните базу и backups надлежащим образом. Если ключ раскрыт, попросите издателя отозвать его и выпустить новый.

## 7. Обновления неактивных плагинов и тем (необязательно)

Обычный SDK в коде плагина исполняется только тогда, когда плагин активен. Аналогично код темы работает только у активной темы. Если нужно обновлять неактивные расширения, используйте MU-loader.

### Неактивные плагины

1. Скопируйте `client/wp-panda-updater.php` как `wp-content/mu-plugins/wp-panda-updater.php`.
2. Скопируйте `client/loaders/wp-panda-plugin-updater-loader.php` как `wp-content/mu-plugins/wp-panda-plugin-updater-loader.php`.
3. В `wp-config.php` укажите корень API:

   ```php
   define('WP_PANDA_VAULT_API_URL', 'https://updates.example.com/wp-json/wp-panda/v1');
   ```

4. В заголовок главного PHP-файла каждого private-плагина добавьте строку:

   ```php
   // Panda Vault Slug: panda-seo
   ```

   Slug должен быть тем же, что slug в продукте Vault. Loader сканирует заголовки плагинов, в том числе неактивных, и регистрирует updater с путём главного файла.
5. Не подключайте один продукт одновременно loader и его собственным bootstrap-кодом, если важен контроль порядка загрузки. SDK защищает от повторной регистрации одинаковых `type:slug`, но загрузчик может зарегистрировать его первым.

### Неактивные темы

1. Скопируйте SDK и `client/loaders/wp-panda-theme-updater-loader.php` в `wp-content/mu-plugins/` под указанными именами.
2. Задайте `WP_PANDA_VAULT_API_URL` как выше.
3. Добавьте в `style.css` private-темы заголовок `Panda Vault Slug: my-theme` (в первые 8 KiB файла); значение должно совпадать со stylesheet/catalog slug и продуктом в Vault.
4. Loader обходит установленные темы, включая неактивные, и регистрирует их updater.

MU-plugins загружаются автоматически; отдельная активация loader не нужна. Папка `mu-plugins` должна существовать. Для клиентской админки лицензий SDK должен быть загружен через один из loaders, а `WP_PANDA_VAULT_API_URL` — определён до его выполнения. Для активных продуктов это также может делать сам SDK в файле продукта.

Не кладите два разных файла с одинаковым объявлением класса SDK; используйте одну центральную копию в `mu-plugins` для loader-сценария. Не задавайте `WP_PANDA_VAULT_API_URL` без HTTPS на production. Для временного локального тестирования SDK допускает HTTP только при явном `WP_PANDA_ALLOW_INSECURE_API` со значением true; не включайте это на публичном сайте.

## 8. REST-адрес и сетевое взаимодействие

URL передаётся без конечной точки, например:

```text
https://updates.example.com/wp-json/wp-panda/v1
```

SDK вызывает:

- `GET {api_url}/check` — проверка нового релиза с Bearer license key;
- `POST {api_url}/license/activate` — регистрация сайта;
- `POST {api_url}/license/deactivate` — освобождение слота при деактивации;
- полученный сервером `package` URL — временная загрузка ZIP, сам ключ в URL не включается.

Клиент использует TLS verification, ограниченные timeout и WordPress HTTP API. При сетевой ошибке SDK скрыто оставляет продукт доступным; обновление не показывается до следующей успешной проверки. Результат ошибки кэшируется до пяти минут.

## 9. Ручная проверка обновления и приёмочные тесты

1. Создайте тестовый продукт в Vault и загрузите первую установленную версию.
2. Установите эту версию на отдельный тестовый WordPress, активируйте ключ.
3. Загрузите более новую версию ZIP; проверьте совпадение заголовка Version и версии релиза.
4. На клиенте запустите **Консоль → Обновления → Проверить ещё раз** и установите предложение штатной кнопкой.
5. Проверьте версию в файлах и число загрузок/last seen в Vault.
6. Без ключа и с неверным ключом убедитесь, что WordPress показывает релиз, но скачивание ZIP отклоняется сервером. Повторите проверку с действительным ключом, активированным для площадки, и убедитесь, что установка проходит.
7. После выдачи подписанной ссылки отзовите лицензию или удалите активацию и проверьте, что скачивание по уже выданной ссылке больше не разрешается.
8. Проверьте превышение лимита, деактивацию, локальное удаление, замену ключа и ручное освобождение слота.
9. Если поддерживаете обновление неактивных продуктов, протестируйте соответствующий loader на неактивном плагине/теме.

## 10. Устранение неполадок

### Страница Panda Updates отсутствует

Проверьте, что SDK действительно подключён на админском запросе, конфигурация валидна и `api_url` задан. Если указан `settings_page`, SDK специально не создаёт страницу — вставьте `wp_panda_updater_license_field()` в callback собственной страницы. Если используете MU-loader, проверьте путь к файлам, константу URL и заголовки slug.

### Блок не появляется на своей странице

Выполните helper после создания updater и в ходе рендеринга страницы. Сверьте `slug` и `type` посимвольно. Убедитесь, что функция возвращает `true`, текущий пользователь имеет `manage_options`, SDK не пропускает продукт из-за HTTP URL/невалидного slug и страница не рендерится раньше регистрации экземпляра.

### Ключ отклонён

Проверьте точное копирование, соответствие ключа продукту и типу, статус лицензии, лимит и исходящий HTTPS. Уточните у издателя, не отозвана ли лицензия. URL сайта берётся из настроек WordPress (`home_url('/')`); неверные `home`/`siteurl`, нестандартный порт или сменившийся путь могут повлиять на идентичность активации.

### Обновление видно, но скачать его не удаётся

Это ожидаемо без лицензии или при неверном ключе: метаданные релиза публичны, а скачивание пакета требует активированную лицензию для этого сайта. Активируйте корректный ключ. Если активация успешна, но пакет всё ещё возвращает 403, проверьте, что ссылка обновлена после активации, площадка не удалена из Vault и лицензия не отозвана. Выданные URL перепроверяют entitlement в момент скачивания.

### Обновление не отображается

Проверьте, что версия релиза выше установленной, версия продукта указана корректно, slug/type совпадают и релиз опубликован. Запустите повторную проверку с учётом пяти минут кэша. Убедитесь, что серверный `api_url` задан как корень namespace, а PHP клиента может обращаться к нему.

### cURL SSL / timeout / недоступный пакет

Проверьте DNS, firewall и CA certificates клиентского сервера, TLS-сертификат Vault, наличие исходящих HTTPS-соединений и REST endpoints. Если запрос обновления прошёл, но ZIP — нет, временная подпись могла истечь; выполните повторную проверку. Не отключайте `sslverify` как постоянное исправление.

### Обновление темы/плагина неактивно не обнаруживается

Код встроенного SDK не исполняется для неактивного продукта. Установите правильный MU-loader, его SDK-копию и URL-константу. Для плагина проверьте `Panda Vault Slug` в главном PHP-файле; для темы — в `style.css` и совпадение со stylesheet slug.

## 11. Разработчикам: гарантии и ответственность

SDK отвечает за запрос/отображение обновлений и операции лицензии; он не выполняет entitlement check при запуске бизнес-функций продукта. Не добавляйте в плагин проверки, которые блокируют интерфейс/функции при отсутствии лицензии, если вы хотите соблюдать обещанное пользователю поведение.

Лимит сайта — организационный контроль по host/port/path, а не доказательство владения доменом. DNS/HTTP challenge, платежи, истечение лицензий, учёт пользователей и самостоятельный портал управления в текущую систему не входят. Не обещайте клиенту функции, которых нет в текущем серверном продукте.

Серверные требования, формат ZIP и правила выпуска/отзыва ключей: **[server/README_RU.md](../server/README_RU.md)**.
